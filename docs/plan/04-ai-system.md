# AI 시스템

## 1. AI 자율성 및 이벤트 시스템
*   **이벤트 빈도 조절:** 플레이어가 마을 분위기를 선택 가능 (예: "느긋한 마을" / "시끌벅적한 마을"). AI의 자율 행동 빈도와 이벤트 발생률을 조절.
*   **높은 자율성:** AI 에이전트가 플레이어 개입 없이도 자발적으로 관계를 형성하고 이벤트를 발생시킴.

## 2. 시뮬레이션 전략
*   **플레이어 접속 중:** 실시간 시뮬레이션 진행. 이벤트 발생 → LLM 호출 → 대사 생성 → 화면 표시.
*   **플레이어 부재 시:** 시뮬레이션 정지. 다음 접속 시 부재 시간을 계산하여 **Catch-up 처리:**
    *   숫자 테이블만으로 "그 사이에 일어났을 법한 이벤트"를 경량 산출 (LLM 호출 없이).
    *   결과를 이벤트 로그에 기록.
    *   접속 시 뉴스 브리핑(자동 재생)으로 하이라이트 요약 + 캐릭터별 말풍선으로 세부 사정 확인 가능.
    *   큰 이벤트(고백, 결혼 등)는 부재 중 보류 → 접속 시 말풍선으로 대기 (상세: [02-relationship.md](02-relationship.md) 참조). 사소한 이벤트만 생성.
    *   부재 시간이 길어도 이벤트가 과하게 쌓이지 않도록 상한선 설정.

## 3. LLM 호출 전략
*   24명 전원이 동시에 LLM을 호출하지 않음.
*   이벤트 대상 캐릭터는 **기존 게임처럼 확률/조건 기반으로 랜덤 선정** (숫자 테이블이 트리거).
*   선정된 캐릭터의 대사/반응 생성에만 LLM 호출 → 이벤트당 1~2회 수준으로 관리.

## 3. LLM 기본 타겟
*   **로컬 Ollama** 기본. BYOK(클라우드 API) 옵션도 제공.
*   ⚠️ 로컬 Ollama 사용 시, 모바일 접속 시에는 서버 PC가 켜져 있어야 함.

## 5. 음성 시스템 (TTS)
*   캐릭터 대사를 TTS로 출력. 어떤 TTS 엔진을 사용할지는 미정.
    *   **후보:** Web Speech API (브라우저 내장, 무료), ElevenLabs/OpenAI TTS (고품질, 유료), 로컬 TTS (Piper 등).
    *   성격/개성에 따라 음높이·속도·톤을 차별화하면 캐릭터 구분에 효과적.

## 6. AI 생성 콘텐츠
*   **AI 동네 뉴스:** 하루 동안 주민들 사이에서 벌어진 사건(싸움, 선물, 연애)들을 요약하여 아나운서 캐릭터가 브리핑. 접속 시 자동 재생.

## 7. 꿈 시스템
*   **템플릿 기반 (LLM 미사용):** 미리 만든 꿈 템플릿 풀에서 랜덤 선택. 캐릭터 이름/관계 등 변수만 치환.
*   **보상:** 꿈 이벤트 시 아이템 획득 가능.
*   **이미지 생성 AI 연동:** 우선순위 낮음. 여유 되면 추후 추가 검토.
*   **LLM 연동:** 필요하다 판단되면 추후 추가. 초기에는 템플릿 풀로 충분.
