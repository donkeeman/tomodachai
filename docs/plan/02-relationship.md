# 관계 시스템

## 1. 하이브리드 관계 관리
*   **숫자 테이블 (내부):** 호감도, 질투, 긴장도(Tension) 등 관계 수치를 내부적으로 관리. 행동 결정의 기본 트리거로 사용.
*   **플레이어 표시:** 수치/색상은 노출하지 않음. 관계 카테고리(친구/연인/부부 등) + 상태 텍스트("좋아함", "엄청 좋아함" 등)만 표시. 상태 텍스트는 내부 수치 구간에 매핑.
*   **관계 이벤트 로그 (히스토리):** 핵심 관계 이벤트(고백, 이별, 재결합, 큰 싸움 등)를 구조화된 로그로 기록. 예: `"A와 B가 day_42에 헤어짐 (사유: C와의 삼각관계)"`. 토큰 부담 없이 서사적 깊이 확보.
*   **LLM (대사 생성/이벤트 해석):** 숫자 테이블 + 이벤트 로그를 읽고, 맥락에 맞는 대사와 반응을 생성하는 "연기" 역할에 집중.

## 2. 관계 단계
모르는 사이 → 지인 → 친구 → 연인 → 결혼까지. 출산/자녀/세대 시스템은 스코프 밖 (규모 과대 방지).
*   베스트 프렌드 → 연인 전환 제한 규칙 없음 (원작의 해당 규칙은 이성 한정 연애 때문이었으므로 제거).
*   성별에 의한 연애 제한 없음.

## 3. 관계의 자유성
*   원작(Collection)에서는 이별 시 재회 불가였으나, 이 프로젝트에서는 **낮은 확률 또는 LLM 판단으로 재결합 가능**.
*   이벤트 로그에 이별/재결합 이력이 남으므로 단순 리셋이 아닌 서사적 재회가 됨.
*   관계 상태의 비가역성을 줄여, 캐릭터 간 관계가 더 유기적이고 현실적으로 흘러가도록 설계.

## 4. 복잡한 관계 시뮬레이션
*   **삼각관계, 라이벌** 등 다자간 관계 형성.
*   질투 유발 시 상황에 맞는 대사 및 행동(피하기, 시비 걸기 등) 자동 생성.
*   재회/재결합 시 이벤트 로그를 참조하여 단순 리셋이 아닌 히스토리 반영 대사 생성 (예: "우리 그때 헤어졌었는데...").

## 5. 싸움 시스템 (1종류로 통합)
*   **플레이어 실시간 목격 시:** 싸움 진행 중 → "말린다" / "지켜본다" 선택 가능. 말리면 중재 시도 (성공/실패), 지켜보면 자연 경과.
*   **플레이어 부재 시:** 이미 싸운 상태로 결과가 남아있음. 이후 한쪽이 "사과하고 싶다" 말풍선 이벤트 발생 가능 → 플레이어가 중재 도움.
*   싸움 결과는 관계 이벤트 로그에 기록.

## 6. 질투 시스템
*   고백 거절, 이별, 삼각관계 패배 등으로 질투 상태 진입.
*   **플레이어 요청:** 질투한 캐릭터가 "저 커플 헤어지게 해줘" 등 방해 공작 요청 → 수락/거절 선택.
*   **AI 자율 행동:** LLM이 질투 상태에 기반하여 자율적으로 행동 생성 (뒷담화, 상대 회피, 시비 걸기, 다른 캐릭터에게 하소연 등). 질투 감정이 관계망 전체에 파급될 수 있음.

## 7. LLM 관계 판단 가드레일
*   관계 전환(특히 우정 → 연애)은 **숫자 테이블의 트리거가 먼저 발생**해야 LLM에게 해당 가능성을 지시.
*   트리거 없이 LLM이 단독으로 관계 상태를 변경하지 못하도록 시스템적으로 제한.
*   프롬프트에 "우정이 깊어진다고 반드시 연애로 발전하지는 않는다" 등의 가드레일 포함. 연애 전환 감도는 조정 필요.

## 8. 맥락 관리 전략
*   캐릭터의 행동/대사 결정 시, 전체 캐릭터 데이터를 넣지 않고 **우선순위 기반으로 관련 맥락을 선별 주입**. 구체적인 선별 기준과 주입량은 구현 단계에서 실험을 통해 결정.
*   주기적으로 LLM이 최근 중요 사건을 요약 압축하여 장기 기억으로 저장.
