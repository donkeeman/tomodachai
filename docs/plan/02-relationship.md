# 관계 시스템

## 1. 관계 수치

### 독립 수치 (직접 관리, 방향성: A→B ≠ B→A)
| 수치 | 범위 | 설명 |
|------|------|------|
| friendship | -100 ~ 100 | 적대 ~ 우호 |
| romance | 0 ~ 100 | 로맨틱 감정 |

### 파생 상태 (수치 조합에서 이벤트 발생 시 판정)
| 상태 | 판단 기준 |
|------|----------|
| 질투 | A→B romance 높음 + B의 romance가 A를 향하지 않음 (B→C가 높다거나) |
| 긴장/갈등 | friendship이 마이너스이거나, 최근 변동폭이 컸을 때 |
| 적대 | friendship이 일정 이하 |

### 플레이어 표시
*   수치/색상은 노출하지 않음.
*   관계 카테고리(친구/연인/부부 등) + 상태 텍스트("좋아함", "엄청 좋아함" 등)만 표시.
*   상태 텍스트는 내부 수치 구간에 매핑.

## 2. 지정 관계 슬롯 (캐릭터당 각 1명)

모든 지정 관계는 **양방향 합의** 기반. 수치는 단방향이지만, 양쪽 모두 임계값을 넘어야 성립.

### 관계 슬롯 (현재 상태, 캐릭터당 각 1명)
| 슬롯 | 조건 | 비고 |
|------|------|------|
| 베프 | A→B friendship ≥ 70 AND B→A friendship ≥ 70 | 서로 가장 친한 상대 |
| 연인/배우자 | 고백 성공 (양방향 합의) | 상호 합의 |
| 원수 | A→B friendship ≤ -50 AND B→A friendship ≤ -50 | 서로 싫어하는 상대. 자연스럽게 희귀 |

### 관계 태그 (이력, 슬롯과 독립)
| 태그 | 수 | 비고 |
|------|---|------|
| 전 연인 | 복수 가능 | 이별 시 자동 부여. 이별 사유(reason) 포함. 재회 시 제거 |

*   태그와 슬롯은 독립적. 전 연인이면서 현재 베프일 수도, 원수일 수도 있음.
*   friendship/romance 수치는 태그와 무관하게 정상적으로 변동.
*   LLM은 태그를 참조하여 대사 톤 조절 (어색함, 미련, 담담함 등).
*   베스트 프렌드 → 연인 전환 제한 규칙 없음.
*   **MVP: 연애는 남녀 간만 가능.** 향후 확장 시 선택 가능하게 변경 검토.

## 3. 관계 단계 전환 (이벤트 트리거)

| 전환 | 조건 | 비고 |
|------|------|------|
| 모르는 사이 → 지인 | 첫 대화 발생 시 자동 | |
| 지인 → 친구 | 양방향 friendship ≥ 30 | |
| 친구 → 베프 | 양방향 friendship ≥ 70 | |
| 고백 가능 상태 | A→B romance ≥ 50, A→B friendship ≥ 20 (A 기준만) | 조건 충족 시 "고백하고 싶어요" 말풍선 |
| 고백 발생 | 플레이어가 "해!" 선택 시 | 부재 중에는 발생하지 않음 (보류) |
| 고백 성공/실패 | **상대 수치 참조하지 않음. 랜덤 확률로 결정.** | 의외의 커플 / 의외의 거절 발생 → 서사적 재미 |
| 연인 → 결혼 | 고백과 동일 방식. 프로포즈 말풍선 → 플레이어 선택 → 랜덤 결과 | 부재 중 발생하지 않음 |
| 싸움 발생 | friendship 마이너스 구간일 때 확률적 | 결과(화해/악화)도 랜덤 |
| 이별 | 연인 상태에서 양방향 friendship ≤ -20 | |
| 원수 성립 | 양방향 friendship ≤ -50 | |

*   출산/자녀/세대 시스템은 스코프 밖 (규모 과대 방지).

## 4. 관계의 자유성
모든 지정 관계는 영구적이지 않으며, 낮은 확률로 해제/전환될 수 있음.

| 전환 | 확률 | 조건 |
|------|------|------|
| 베프 → 해제 | 낮음 | 싸움 이벤트 발생 시 |
| 원수 → 해제 | 매우 낮음 | 화해 이벤트 발생 시 |
| 연인 → 이별 | 낮음 | friendship 하락 시 |
| 이별 → 재회 | 매우 낮음 | 랜덤 또는 LLM 판단 |

*   모든 전환은 이벤트 로그에 기록 → LLM이 "우리 베프였는데...", "원수였던 우리가..." 등 히스토리 반영 대사 생성.
*   관계 상태의 비가역성을 줄여, 캐릭터 간 관계가 더 유기적이고 현실적으로 흘러가도록 설계.
*   **기억 유지:** 싸움 등으로 friendship이 떨어져 "지인" 상태로 돌아가거나 슬롯에서 해제되더라도, 이벤트 로그는 지워지지 않음. 다시 친해질 때 LLM이 과거 기억을 참조하여 대사 생성 ("저희 예전에 크게 싸웠었죠..."). 원작처럼 초면처럼 리셋되지 않음.

## 5. 이별/이혼 사유 시스템

이별 사유에 따라 수치 영향, LLM 대사, 재회 확률이 달라짐. 이벤트 로그에 reason 태그로 기록.

| 사유 | 설명 | 떠난/발의한 쪽 | 당한 쪽 | 재회 확률 |
|------|------|--------------|---------|----------|
| 합의 (mutual) | 서로 맞지 않아서 원만하게 | friendship 소폭↓, romance↓ | 동일 | 중간 |
| 싸움 (fight) | 크게 싸우고 감정적으로 | friendship↓↓, romance↓ | friendship↓↓, romance 유지(미련) | 낮음 |
| 바람 (cheating) | 한쪽이 다른 캐릭터와 (아래 상세) | friendship↓, romance↓ | friendship↓↓↓, romance 유지, 질투 상태 | 매우 낮음 |
| 권태 (boredom) | 특별한 사건 없이 서서히 멀어짐 | friendship 유지, romance↓↓ | friendship 유지, romance↓ | 중간~높음 |
| 삼각관계 (triangle) | 제3자 개입으로 관계 파탄 | friendship↓, romance↓ | friendship↓↓, 질투 상태, 제3자에게 적대 | 낮음 |
| 오해 (misunderstanding) | 사소한 오해가 커져서 | friendship↓, romance 소폭↓ | friendship↓, romance 소폭↓ | 높음 |

### 바람(cheating) 발생 경로

**경로 1: 마음이 흔들림 (자연 발생)**
1.  A와 B가 연인인데, A→C romance가 대화 델타 누적으로 상승.
2.  일정 수준 넘으면 A가 "다른 사람이 신경 쓰여요..." 말풍선.
3.  플레이어 선택:
    *   **"솔직해져 봐"** (부추기기) → A가 B에게 이별 통보 → `cheating` 이별.
    *   **"다시 생각해 봐"** → A가 다시 생각... 하지만 **최종 판단은 LLM이 결정**. 돌아갈 수도 있고, 결국 이별 통보할 수도 있음.
    *   **"B를 생각해"** → romance↓ 보정이 들어가지만, 역시 LLM 최종 판단.

**경로 2: 고백 수락**
1.  A와 B가 연인인데, C가 A에게 고백 → A가 수락.
2.  **연인이 있는 캐릭터에게 고백 가능** (일본판 방식).
3.  수락 시 기존 연인과 `cheating` 사유로 자동 이별.

**헤어지고 싶다 이벤트**
*   연인 상태에서 캐릭터가 "헤어지고 싶어요..." 말풍선.
*   플레이어 선택:
    *   **"그래, 헤어져"** → 이별 진행.
    *   **"다시 생각해 봐"** → 캐릭터가 상대에게 이야기하러 감. **결과는 LLM 판단** (화해할 수도, 결국 이별 통보할 수도 있음).

### 이별 사유 결정 방식
*   시스템이 조건 기반으로 자동 판정 (LLM이 판단하지 않음).
    *   양방향 friendship 하락 + 특별한 사건 없음 → `boredom`
    *   싸움 이벤트 직후 이별 조건 충족 → `fight`
    *   제3자 고백 수락 또는 제3자 romance 초과 → `cheating`
    *   삼각관계 상태에서 이별 → `triangle`
    *   그 외 → `mutual` 또는 `misunderstanding` (랜덤)

*   이벤트 로그 예시: `{ "id": 42, "type": "breakup", "participants": [1, 2], "reason": "cheating", "day": 42 }`
*   LLM이 reason 태그를 참조하여 사유별로 다른 대사/감정 생성.
*   재회 시에도 이전 이별 사유를 참조 ("그때 바람피운 거 아직도 잊은 거 아니에요..." 등).
*   이별 후 각각 다른 사람과 만나더라도, 이전 연인에 대한 아쉬움/미련이 대화에 반영될 수 있음.

## 6. 고백 재시도 시스템
*   거절 시 romance 소폭 하락.
*   같은 상대에게 **최대 3회**까지 재시도 가능.
*   재시도 조건: 거절 후에도 romance ≥ 50이면, 일정 시간 후 "다시 고백할래요" 말풍선 발생 가능.
*   3회 차인 경우 단념: romance 강제 대폭 하락 + "이제 포기할게요..." 이벤트.
*   플레이어가 "그만해"를 선택하면 즉시 단념 처리.

|------|----------|----------|------|
| 원수 | 높음 | - | |
| 일반 (마이너스) | 기본 | - | |

| 연인 | 낮음 | - | 이미 연인이니 고백 없음 |

## 9. 복잡한 관계 시뮬레이션
*   **삼각관계:** A→B romance 높음 + B의 romance가 C를 향할 때 → A가 질투 상태 진입.
*   질투 유발 시 상황에 맞는 대사 및 행동(피하기, 시비 걸기 등) 자동 생성.
*   재회/재결합 시 이벤트 로그를 참조하여 단순 리셋이 아닌 히스토리 반영 대사 생성.

## 10. 싸움 시스템 (1종류로 통합)
*   **플레이어 실시간 목격 시:** 싸움 진행 중 → "말린다" / "지켜본다" 선택 가능. 말리면 중재 시도 (성공/실패), 지켜보면 자연 경과.
*   **플레이어 부재 시:** 이미 싸운 상태로 결과가 남아있음. 이후 한쪽이 "사과하고 싶다" 말풍선 이벤트 발생 가능 → 플레이어가 중재 도움.
*   싸움 결과는 관계 이벤트 로그에 기록.

## 11. 질투 시스템
*   **발동 조건:** A→B romance 높음 + B의 romance가 A를 향하지 않을 때 (파생 상태로 판정).
*   **플레이어 요청:** 질투한 캐릭터가 "저 커플 헤어지게 해줘" 등 방해 공작 요청 → 수락/거절 선택.
*   **AI 자율 행동:** LLM이 질투 상태에 기반하여 자율적으로 행동 생성 (뒷담화, 상대 회피, 시비 걸기, 다른 캐릭터에게 하소연 등). 질투 감정이 관계망 전체에 파급될 수 있음.

## 12. LLM 관계 판단 가드레일
*   관계 전환(특히 우정 → 연애)은 **숫자 테이블의 트리거가 먼저 발생**해야 LLM에게 해당 가능성을 지시.
*   프롬프트에 "우정이 깊어진다고 반드시 연애로 발전하지는 않는다" 등의 가드레일 포함.

## 13. 관계 이벤트 로그
*   핵심 관계 이벤트(고백, 이별, 재결합, 큰 싸움 등)를 구조화된 로그로 기록.
*   예: `"A와 B가 day_42에 헤어짐 (사유: C와의 삼각관계)"`.
*   토큰 부담 없이 서사적 깊이 확보.

## 14. 궁합 시스템
*   **입력 요소:** 성격 유형, 혈액형, 별자리 + 랜덤 요소. 여러 지표가 복합적으로 작용.
*   **기본적으로 재미/참고용.** 관계를 강제하지 않음.
*   **효과 범위:**
    *   아직 관계가 시작되지 않은 사이 → 초기 friendship/romance 상승에 약간의 가산점 (x0.7~x1.3).
    *   이미 관계가 형성된 후 → 궁합 영향 없음. 기존 관계 수치와 이벤트가 우선.
    *   연인이 있는 캐릭터가 궁합 좋은 다른 캐릭터 때문에 헤어지고 붙으려 하지는 않음.
*   **랜덤성:** 같은 성격/혈액형/별자리 조합이어도 매번 다른 궁합이 나올 수 있도록 캐릭터 생성 시 랜덤 시드 포함.
*   **구체적인 공식:** 구현 단계에서 실험을 통해 결정.

### 궁합별 관계 진행 속도 (시뮬레이션 결과, 기본 델타 +1~4, 만남 30%)
| 궁합 | 친구 (≥30) | 베프 (≥70) | 고백 가능 (r≥50) |
|------|-----------|-----------|----------------|
| 좋음 (x1.3) | ~5일 | ~12일 | ~17일 |
| 보통 (x1.0) | ~6일 | ~15일 | ~22일 |
| 나쁨 (x0.7) | ~9일 | ~22일 | ~27일 (도달 어려움) |

## 15. 수치 변동표

### 대화 (기본)
*   **기본 델타:** friendship +1~4, romance +0.5~2
*   이벤트 발생 시 만남 대상은 랜덤 선정

### 이벤트별 변동 (잠정값, 조정 필요)
| 이벤트 | 결과 | 시도한 쪽 | 당한 쪽 |
|--------|------|----------|---------|
| 고백 | 성공 | romance +15~20, friendship +10 | romance +10, friendship +10 |
| 고백 | 거절 | romance -5~8, friendship -3~5, 만족도↓ | friendship -3 |
| 고백 3회 거절 | 단념 | romance -40~50 (강제) | - |
| 화해 시도 | 성공 | friendship +12~15 | friendship +12~15 |
| 화해 시도 | 거절 | friendship -5~8, 만족도↓ | friendship -5 |
| 싸움 | - | friendship -15~20 | friendship -15~20 |
| 이별 (합의) | - | romance -20~30, friendship 소폭↓ | 동일 |
| 이별 (싸움) | - | romance -10~15, friendship -25~30 | romance 유지(미련), friendship -25~30, 만족도↓↓ |
| 이별 (바람) | - | romance -15, friendship -15 | romance 유지, friendship -30~40, 질투 상태 |
| 이별 (권태) | - | romance -25, friendship 유지 | romance -15, friendship 유지 |
| 이별 (오해) | - | romance -10, friendship -10 | romance -10, friendship -10 |

## 16. 수치 자연 변동

### friendship
*   안 만나면 서서히 감소 (0을 향해 수렴). **감소 주기: 하루 1회, -0.5~1 정도.** 대화 1회(+1~4)로 충분히 상쇄되는 수준.
*   단, 친구/베프 슬롯인 캐릭터는 시스템이 같은 장소에 자주 배치 → 사실상 유지됨.
*   지인 수준(낮은 friendship)은 안 만나면 서서히 소원해짐.

### romance
*   자연 감소 가능: 안 만나면 서서히 식음.
*   자연 증가 가능: 자주 만나면 올라갈 수 있음 (궁합 + 대화 델타).
*   다른 캐릭터와 자주 만나면 그쪽 romance가 올라가면서 기존 쪽이 상대적으로 정체/감소.

### 연인/배우자 상태
*   연인/배우자 된 후에도 friendship/romance 계속 변동.
*   관리 안 하면 (플레이어가 방치하면) friendship 하락 → 이별/이혼 가능.

### 초기값
*   첫 만남 시 friendship/romance 모두 0에서 시작.
*   **첫인상 보너스:** 첫 대화 시 궁합/성격 조합에 따라 초기 델타가 달라짐. "첫 만남에 바로 통한 두 사람" vs "첫인상 별로였던 두 사람" 발생 가능.

## 17. 맥락 관리 전략
*   캐릭터의 행동/대사 결정 시, 전체 캐릭터 데이터를 넣지 않고 **우선순위 기반으로 관련 맥락을 선별 주입**. 구체적인 선별 기준과 주입량은 구현 단계에서 실험을 통해 결정.
*   주기적으로 LLM이 최근 중요 사건을 요약 압축하여 장기 기억으로 저장.
