# 플레이어 시스템

## 1. 플레이어 개입
*   **캐릭터 말풍선 이벤트:** 캐릭터가 말풍선을 띄우면 플레이어가 반응할 수 있음.
    *   관계 고민 상담 (아래 상담 시스템 참조).
    *   고백/프로포즈 허락 요청 ("고백하고 싶어요" → "해!" / "하지마").
    *   요구사항 들어주기 (아이템, 음식 등).
    *   미니게임 참여.
*   **물리적 간섭:** 캐릭터를 집어서 다른 캐릭터 옆에 배치 → 만남/상호작용 유도 (최종 반응은 캐릭터 성격에 따라 AI가 결정).
*   **펫 상호작용:** 쓰다듬기 등 직접 인터랙션.
*   **아이템 선물:** 캐릭터 페르소나에 기반한 동적 반응.

## 2. 상담/선택지 시스템
캐릭터가 관계에 대해 상담을 요청하면, 플레이어가 선택지를 골라줌. 선택 결과가 수치에 영향.

### 상담 유형
| 상담 내용 | 선택지 예시 | 영향 |
|----------|-----------|------|
| "ㅇㅇ와 친구가 되고 싶은데 어떤 주제로 이야기하면 좋을까요?" | 취미 / 음식 / 날씨 / 운동 등 | 상대 취향에 맞으면 friendship 보너스 |
| "어떤 말투로 말을 걸면 좋을까요?" | 밝게 / 진지하게 / 장난스럽게 / 조용히 등 | 상대 성격에 맞으면 보너스 |
| "ㅇㅇ에게 선물을 주고 싶은데 뭐가 좋을까요?" | 음식 / 액세서리 / 편지 등 | 상대 선호도에 맞으면 friendship/romance 보너스 |
| "고백하고 싶어요" | "해!" / "하지마" / "좀 더 친해지고 나서" | 관계 이벤트 트리거 또는 보류 |
| "ㅇㅇ랑 싸웠어요... 어떡하죠?" | "사과해" / "시간을 둬" / "네가 맞아" | 화해 시도 방식 결정 → 성공률에 영향 |

### 선택지 매칭 로직
*   플레이어의 선택 → 상대 캐릭터의 성격/취향과 매칭 → 보너스 배율 적용.
*   정답이 명확하지 않도록 설계: 같은 상대라도 상황에 따라 최적 선택이 달라짐.
*   **선택지 생성:** 기본 선택지 풀을 미리 만들되, LLM이 상황에 맞는 선택지를 동적으로 생성하는 것도 고려.

## 3. 경제 시스템
*   **돈 관리:** 플레이어가 직접 관리. 캐릭터가 자율적으로 소비하지 않음.
*   **구매 흐름:** 플레이어가 상점(식료품점, 의류점, 인테리어점)에서 구매 → 캐릭터에게 지급.
*   **캐릭터 요청:** "이거 먹고 싶어요" / "이거 입고 싶어요" 말풍선 → 플레이어가 들어줄지 선택. LLM이 캐릭터 선호도 기반으로 요청 생성.
*   **수입원:** 모금함 (하루 1회), 미니게임 보상 등.

## 4. 아이템 시스템
*   **초기 범위 (Phase 1~2):** 음식 + 선물용 잡화 (관계에 영향 주는 것 위주).
*   **확장 범위 (Phase 3~4):** 의류, 인테리어, 모자 등 점진 확대.
*   **설계 원칙:** 아이템 스키마를 범용으로 설계 (`{ id, category, name, effect }` 등)하여 카테고리 추가 시 시스템 변경 없이 데이터만 추가.

## 5. 펫 시스템
*   캐릭터의 소유물(오브젝트)로 취급. 펫 자체에 AI 에이전트는 부여하지 않음.
*   **한 캐릭터당 최대 1마리.** 종류는 별도 제한 없음 (추후 결정).
*   **획득 방법:** 입양 등 간단한 방식.
*   **영향 범위:**
    *   대화 소재로 활용 (펫 자랑, 펫 고민 등).
    *   플레이어가 펫과 상호작용 가능 (쓰다듬기 등).
    *   캐릭터 기분에 영향 (돌봄으로 스트레스 해소 등).
