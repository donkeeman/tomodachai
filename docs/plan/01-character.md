# 캐릭터 시스템

## 1. 캐릭터 생성
*   **캐릭터 생성 흐름:** 외형 편집 → 프로필 입력 → 음성 설정 → 성격 설정 → 입주 완료.
*   **외형 (3D 로우폴리, 파츠 조립):**
    *   기본 바디 모델 1개 + 교체 가능한 파츠. 런타임 조합.
    *   에셋 제작: 블렌더 MCP 활용.
    *   애니메이션은 기본 바디에 공유 적용 → 24명분 개별 제작 불필요.

    **MVP 파츠 목록:**
    | 파츠 | 방식 | 시작 수량 |
    |------|------|----------|
    | 얼굴형 | 메쉬 교체 | 5~8종 |
    | 피부색 | 컬러 변경 | 8~10색 |
    | 눈 | 베이스 + 속눈썹 레이어 분리 | 베이스 8종, 속눈썹 4종+없음 |
    | 눈 색 | 컬러 변경 | 6~8색 |
    | 눈썹 | 메쉬 교체 | 5~6종 |
    | 코 | 메쉬 교체 | 4~5종 |
    | 입 | 메쉬 교체 | 5~6종 |
    | 앞머리 | 메쉬 교체 (뒷머리와 분리) | 8~10종 |
    | 뒷머리 | 메쉬 교체 (앞머리와 분리). 묶은 머리(포니테일, 트윈테일 등)도 뒷머리 프리셋에 포함 | 8~10종 |
    | 머리색 | 컬러 변경 | 8~10색 |
    | 안경 | 메쉬 교체 + 없음 | 4~5종+없음 |
    | 체형 | 본 스케일 조절 | 파라미터 (키/체격) |

    **이후 확장:**
    *   파츠 종류 추가 (안경, 수염, 점, 귀, 페이스페인트 등)
    *   각 카테고리 수량 증가
    *   위치/크기 미세 조절 (눈 간격, 코 높이 등)
*   **프로필 설정 항목:**
    *   이름 (성 / 이름). 닉네임은 생성 시 입력하지 않음.
    *   생일 (→ 별자리 자동 도출, 생일 이벤트 트리거)
    *   혈액형 (A/B/O/AB)
    *   좋아하는 색 (기본 복장 색상 결정)
    *   성별
*   **혈액형·별자리 활용:** 단순 장식이 아닌 **관계 영향 인자**로 활용. 궁합 시스템에 성격 + 혈액형 + 별자리가 복합적으로 영향.

## 2. 별명 시스템 (이벤트 기반)
*   캐릭터 간 친밀도가 일정 수준에 도달하면 "별명 지어줘도 돼?" 이벤트 발생 → 플레이어가 별명 입력.
*   캐릭터마다 서로 다른 별명을 부를 수 있음 (A는 B를 "철수"로, C는 B를 "수수"로 부르는 등).
*   LLM이 대사 생성 시 관계 단계와 별명 데이터를 참조하여 호칭 반영.

## 3. 성격 시스템
*   **16가지 고정 성격 유형:** 원작과 동일한 4계통 × 4형 = 16가지. 향후 여유가 되면 하위 분기 형태로 확장 가능.

    | 계통 | 유형 1 | 유형 2 | 유형 3 | 유형 4 |
    |------|--------|--------|--------|--------|
    | **안정파** (ナゴミ系/Easygoing) | 외유내강형 | 다정다감형 | 우유부단형 | 순진무구형 |
    | **사교파** (ノリ系/Outgoing) | 좌충우돌형 | 시끌벅적형 | 재기발랄형 | 명랑쾌활형 |
    | **주도파** (ドライ系/Confident) | 시원시원형 | 속전속결형 | 유아독존형 | 거두절미형 |
    | **신중파** (クール系/Independent) | 완전무결형 | 유비무환형 | 우물쭈물형 | 묵묵부답형 |
*   **성격 설정 방식 (슬라이더 기반):**
    *   **슬라이더 5개** (각 0~8):
        *   Movement (느림 ↔ 빠름) — 행동 속도에 영향
        *   Speech (유순함 ↔ 직설적) — 말투에 영향
        *   Expressiveness (냉정 ↔ 감정적) — 감정 표현에 영향
        *   Attitude (진지 ↔ 여유) — 태도에 영향
        *   Overall (특이 ↔ 평범) — 성격 유형 판정에는 무관. 병맛 이벤트의 톤 강도 및 내용의 기이함 정도에 영향. 특이 쪽이면 이벤트 내용 자체가 황당해지고, 평범 쪽이면 일상적인 범위 내에서 전개.
    *   **유형 결정:** Movement+Speech 합산 → 4계통 결정, Expressiveness+Attitude 합산 → 4형 결정. 구간은 균등 분할. Overall은 유형 판정에 불참.
    *   **슬라이더 세부 값의 역할:** 유형이 같아도 슬라이더 수치에 따라 행동/말투의 강도가 다름. LLM 프롬프트에 강도 정보로 전달.
    *   **자연어 입력 보조:** 유저가 텍스트로 성격을 설명하면, LLM이 분석하여 슬라이더 값을 자동 세팅. 이후 수동 미조정 가능.
    *   결과물은 항상 슬라이더 값(= 16가지 유형 중 하나)으로 귀결되어 시스템 일관성 유지.

## 4. 기분/만족도 시스템

### satisfaction (만족도) — 장기 수치
*   캐릭터별 내부 수치. **레벨업 경험치 역할.** 마이너스 가능.
*   좋아하는 것(음식, 옷 등)을 주면 상승, 싫어하는 것을 주거나 방치하면 하락.
*   **레벨업:** 임계값(레벨 무관 통일) 도달 시 레벨업 → 리셋. 플레이어가 보상 선택 (아이템 / 말버릇 / 노래 / 인테리어 중 택1).
*   **절망:** satisfaction < 0 이면 절망 상태. 도깨비불 이펙트, 모션/대사 변화. 절망 트리거: 고백 거절, 이별, 화해 실패 등으로 satisfaction이 강제 마이너스로 하락.

### mood (기분) — 단기 감정 상태
*   satisfaction과 별개. 지금 이 순간의 감정.
*   **3축 조합:**
    *   happiness (행복): 좋아하는 음식, 친구 대화 → ↑ / 싫어하는 음식, 싸움 → ↓
    *   energy (에너지): 대화, 활동 → ↑ / 배고픔, 거절 → ↓
    *   stress (스트레스): 싸움, 배고픔, 거절 → ↑ / 친구 대화, 시간 경과 → ↓
*   조합으로 다양한 감정 표현 (신남, 평온, 짜증, 우울 등).
*   이모티콘/이펙트 + 표정 변화 + 모션/대사 변화. LLM에 수치 전달하여 대사 톤 반영.
*   시간 경과 시 중립으로 수렴.

| | satisfaction | mood |
|--|-------------|------|
| 성격 | 장기, 레벨업/절망용 | 단기, 현재 감정 |
| 변동 | 이벤트로 크게 변동 | 일상적으로 수시 변동 |
| 마이너스 | → 절망 상태 | → 기분 나쁨 (우울 표정 등) |
| 영향 | 경험치 | LLM 대사 톤, 표정/이펙트 |

### 배고픔
*   시간 경과에 따라 발생. 음식을 주면 해소.
*   배고프면 satisfaction↓, mood(happiness↓, energy↓, stress↑).

### 아픔
*   감기 / 배탈 2종류. 말풍선으로 알림.
*   약 아이템을 줘야 회복. 약은 소원 들어주기 보상 등으로 랜덤 획득.
*   도깨비불 이펙트.

## 5. 캐릭터별 선호도
*   **생성 시 전체 아이템의 선호 구간 + 구간 내 순위가 확정. 이후 변동 없음.**
*   플레이어가 먹여보거나 입혀보면서 발견하는 재미.

### 선호 구간 (5단계)
| 구간 | 수량 | 리액션 (음식 기준) | 리액션 (아이템/옷 기준) |
|------|------|-------------------|----------------------|
| 최애 | 2개 | 극적 연출 (눈 커지고 춤 등) | 뛸듯이 기뻐함 |
| 좋아함 | n개 | 웃으며 맛있게 먹음 | 기뻐함 |
| 보통 | 대부분 | 무난한 반응 | 무난한 반응 |
| 싫어함 | n개 | 찡그림 | 실망 |
| 최악 | 2개 | 토하거나 쓰러짐 | 노골적 불만 |

### 구간 내 순위
*   같은 구간 안에서도 순위가 있어 만족도 상승/하락폭이 미세하게 다름.
*   구간은 절대 변하지 않음 (좋아함→최애 승격 불가).

### 플레이어에게 표시
*   **표시됨:** 최애 2개 + 좋아함/보통 합쳐서 상위 n개 + 최악 2개 (발견 시에만)
*   **표시 안 됨:** 싫어함 구간 → 리액션으로만 유추
*   순위 자체는 직접 표시하지 않음 → 수치 차이로 추측
*   **줘본 여부 표시:** 아이템 리스트에서 해당 캐릭터에게 줘봤는지 마킹 (도감식)

### 성격 계통 선호
*   생성 시 랜덤으로 **선호 계통 1개** 또는 **비선호 계통 1개** 중 하나만 배정.
*   선호: 해당 계통 캐릭터와 초기 관계 형성에 미세한 가산점.
*   비선호: 해당 계통 캐릭터와 초기 관계 형성에 미세한 감산점.
*   영향 크지 않음.

### 선호도 적용 대상
*   **음식:** 전체 아이템 순위 배열 (인덱스 = 순위). 5단계 구간으로 잘라서 표시.
*   **의류:** 스타일 카테고리 기반. 선호 스타일 1개 + 비선호 스타일 1개. 캐릭터가 "캐주얼한 옷 입고 싶어요" 같은 요청으로 힌트. 아이템에 스타일 태그 필요. (스타일 태그 목록은 TODO)
*   **인테리어:** 테마 카테고리 기반. 선호 테마 1개 + 비선호 테마 1개. 아이템에 테마 태그 필요. (테마 태그 목록은 TODO)

### 의류 시스템
**슬롯 구조 (내부):** 상의 / 하의 / 신발 분리.
**MVP:** 일체형(상의+하의 세트) 옷만 제공. 슬롯은 분리되어 있으므로 이후 개별 상의/하의/신발 추가 시 자연스럽게 확장.

**카테고리:**
*   공용 (남녀 무관)
*   남성복
*   여성복
*   특수복 (코스튬, 직업복, 이벤트 복장 등)

**색/텍스처 바리에이션:** 같은 메쉬 + 컬러/텍스처 변경으로 수량 확보. 바리에이션 없는 옷도 있음.

### 인테리어 시스템
*   방 통째 교체 (테마 단위).
*   세부 테마 목록은 구현하면서 추가.

## 6. 노래 시스템
*   **멜로디:** 장르별 템플릿 미리 제작. 캐릭터에게 노래를 선물로 부여.
*   **장르:** 트로트(엔카), 아이돌, 발라드, 락(메탈 포함), 랩, 뮤지컬/오페라, 동요, 찬송가/장엄한 풍.
*   **가사 설정 (4가지 방식):**
    1. 기본값 가사 (장르별 기본 제공)
    2. 단어 하나하나 직접 지정 (원작 방식)
    3. 분위기 입력 → LLM 생성 ("슬픈 느낌으로", "짝사랑 노래" 등)
    4. 랜덤 버튼 → LLM 랜덤 생성
*   **솔로 / 듀엣 / 그룹:**
    *   같은 장르의 노래를 가진 캐릭터 2명 이상이면 합동 공연 가능.
    *   **파트 배정:** 플레이어가 직접 지정 (1절 A, 2절 B, 후렴 같이 등) 또는 자동 배정.
    *   조합에 따른 재미 (베프끼리, 원수끼리 등).
*   **출력:** TTS로 가사를 읽어줌. 콘서트홀 등에서 공연 이벤트로 활용.
*   **BGM 스타일:** 레트로 지향. DS/3DS 사운드폰트 또는 로우파이 중 검토 중. (TODO)

## 7. 미니 개성
*   성격 유형과 별개로, 미세한 행동 특성을 캐릭터별로 부여.
*   LLM 프롬프트에 행동 특성 필드로 주입하여 대사/행동 묘사에 자연스럽게 반영.

### 카테고리
| 카테고리 | 예시 |
|---------|------|
| 걷는 방식 | 뒤뚱뒤뚱, 씩씩하게, 느릿느릿 |
| 먹는 방식 | 허겁지겁, 천천히 음미 |
| 대기 모션 | 까불까불, 팔짱, 두리번, 졸기 |
| 서있는 자세 | 반듯, 한쪽 발 기대기 |

*   **대기 모션:** 성격 유형에 따라 기본값 자동 배정 (노리계→까불, 쿨계→팔짱 등). 미니 개성으로 덮어쓰기 가능.
*   나머지 카테고리는 미니 개성으로 부여.

## 8. 말버릇 시스템
*   **5종류 (감정별):** 일반 / 기쁠 때 / 화날 때 / 슬플 때 / 걱정할 때. 각각 별도 설정.
*   **입력 방식:** 플레이어가 직접 입력 가능. 자동 생성 옵션도 제공 (성격 기반으로 LLM이 추천).
*   **LLM 반영 방식:** 단순히 문장 끝에 붙이는 것이 아니라, LLM이 문맥에 맞춰 대사에 자연스럽게 녹여서 출력. 말버릇이 대화 흐름 속에 유기적으로 섞이도록 프롬프트 설계.

## 9. 병맛/초현실 요소 (하이브리드 방식)
원작의 핵심 매력인 소소한 병맛 유머를 적극 반영.
*   **비주얼/연출 병맛:** 꿈 시퀀스, 과장된 리액션 애니메이션 등은 미리 만든 이벤트 템플릿 풀로 제공.
*   **텍스트/서사 병맛:** LLM이 프롬프트 기반으로 매번 새로운 엉뚱한 대사/상황을 생성.
*   **조합:** 미리 만든 연출 틀 + LLM이 생성한 텍스트를 끼워넣는 방식 (예: "꿈 시퀀스 연출 템플릿" + LLM이 생성한 꿈 내용).
